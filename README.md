# LitePMS → Bitrix24 Adapter (PHP)

Каркас приложения-адаптера по техническому заданию `LitePMS-Bitrix24-TZ.md` — интеграция
системы бронирования **LitePMS** с лидами **Bitrix24**, где **CRM выступает агрегатором**
всех заявок и броней, а обработка ведётся в LitePMS.

Направление обмена — **только A (LitePMS → Bitrix24)**: исходящие webhook-уведомления
LitePMS принимаются адаптером и превращаются в создание/обновление лидов CRM. Направление
B (лид → LitePMS) не выполняется — входящего REST-API у LitePMS нет.

## Архитектура

```
                    (исходящие вебхуки, POST)
LitePMS  --------------------------->  [ Адаптер (этот каркас) ]  --->  Bitrix24 (REST, лиды)
                                         |
                                         +---> SQLite (очередь + пары «бронь↔лид» + лог)
```

Роль **адаптера**:

1. Принять исходящее уведомление LitePMS (POST на `/webhook`) и **сразу вернуть `200`**
   (иначе LitePMS может заблокировать доставку — ТЗ разд. 8.3.1).
2. Поставить событие в **очередь** (SQLite).
3. Фоновый **воркер** извлекает события и выполняет `crm.lead.add` / `crm.lead.update`
   с маппингом полей и связкой по `EXT_ID`.

## Установка

Требования: **PHP ≥ 8.1**, расширения `pdo_sqlite`, `curl`, `json`, и [Composer](https://getcomposer.org/).

```bash
cd litepms-b24-adapter
composer install
cp config/config.dist.php config/config.local.php   # заполнить секреты и маппинг
```

Проверка базовой логики (без БД и внешних вызовов):

```bash
composer test
```

## Настройка

В `config/config.local.php` заполните:

| Ключ | Что указать |
|------|-------------|
| `app.endpoint_secret` | Секретный ключ, который адаптер ждёт в заголовке `X-LitePMS-Adapter-Key` |
| `bitrix24.webhook_url` | Входящий REST-вебхук портала вида `https://<портал>/rest/<user_id>/<токен>/` |
| `mapping.*` | Коды пользовательских полей лида (`UF_CRM_*`) — **подтвердить на портале** |
| `status_map` | Соответствие `status_id` LitePMS → стадия воронки лида |
| `source_map` | Соответствие `service_id` LitePMS → источник (`SOURCE_ID`) CRM |

Секреты не должны попадать в репозиторий и логи — `config.local.php` в `.gitignore`.

## Запуск

### Web-эндпоинт

Деплой папки `public/` как docroot. В настройках LitePMS webhook-уведомлений укажите адрес:

```
https://ваш-домен/webhook
```

и добавьте заголовок `X-LitePMS-Adapter-Key: <секрет>` (если LitePMS позволяет отправлять
произвольные заголовки). Если нет — защита по секретному адресу + проверка источника на уровне
прокси/файрвола (ТЗ разд. 11).

Healthcheck:

```
GET https://ваш-домен/health   → 200 {"status":"ok"}
```

### Фоновый воркер

Воркер обрабатывает очередь. Запуск раз в минуту через cron обеспечивает SLA ≤ 5 минут
(ТЗ разд. 13.2):

```
* * * * * php /путь/к/adapter/bin/worker.php >> /var/log/litepms-worker.log 2>&1
```

Либо — постоянный процесс под [supervisor](http://supervisord.org/) (цикл сна в воркере).

## Формат webhook-уведомлений LitePMS

Поддерживаются события (ТЗ разд. 8.3):

- **бронь** — `new_booking`, `edit_booking`, `delete_booking`, `booking_module`, `channel_manager_booking`
  (поля `booking_id`, данные гостя, даты, `person`, `price`, `status_id`, `service_id`,
  атрибуция `ym_clid`/`etext`/`yclid`);
- **оплата** — `booking_module_payment` (`invoice_id`, `price`, `pay_service`);
- **предзаявка** — `booking_module_request` (`name`, `phone`, `comment`).

Обработка по типам в `SyncService`:

| Событие | Действие адаптера |
|---------|-------------------|
| создание брони | создать лид (`crm.lead.add`) с `EXT_ID = booking_id` |
| изменение брони | обновить лид (`crm.lead.update`) по `EXT_ID` |
| удаление брони | обновить лид (стадия «отменено»), если лид есть; иначе не создавать |
| оплата | записать отметку/сумму оплаты в лид |
| предзаявка | залогировать (TODO: создание лида из заявки при необходимости) |

## Связка «бронь ↔ лид»

Пара идентификаторов хранится:

- в **лиде** — поле `EXT_ID` (`UF_CRM_EXT_ID` в конфиге) = `booking_id` из LitePMS;
- локально — таблица `links` (`booking_id` ↔ `lead_id`) для быстрого поиска без запроса к CRM.

Перед созданием лида выполняется поиск по `EXT_ID` (`crm.lead.list`) — при совпадении
обновляем существующий лид, а не создаём дубль (ТЗ разд. 6, 9.3).

## Очередь, ретраи, логи

- Все события попадают в **SQLite-очередь**; webhook возвращает `200` мгновенно.
- При сбое — **повторные попытки по экспоненциальной схеме** (до `queue.max_attempts`,
  задержка `backoff_base_ms × 2^attempt`), затем пометка «ошибка» (статус `error`,
  повторно не обрабатывается) (ТЗ разд. 10.1).
- Зависшие задачи в статусе `processing` возвращаются в очередь воркером
  (`queue.stale_after_sec`).
- **Идемпотентность** (ТЗ разд. 9.1): повторная доставка того же тела не создаёт дубль.
- **Логи** не содержат чувствительные данные: телефоны и email маскируются
  (ТЗ разд. 10.2).

## Отчётность

Отчёт по синхронизации за период генерируется CLI:

```bash
php bin/report.php 2026-10-01 2026-10-31
```

По умолчанию — CSV (UTF-8 BOM, открывается в Excel). Для нативного **XLS/XLSX** подключите
`phpoffice/phpspreadsheet` — заготовка `XlsReporter::exportXlsx()` (ТЗ разд. 10.2).

## Безопасность

- Только **HTTPS** (ТЗ разд. 11).
- Секреты — в `config.local.php` / переменных окружения, **не** в коде и логах.
- LitePMS не подписывает webhook'и (HMAC нет) — endpoint проверяет фиксированный секретный
  заголовок `X-LitePMS-Adapter-Key` и должен быть на секретном, непубликуемом адресе.
- Все входящие данные проходят валидацию и санитизацию (парсер отклоняет некорректный payload).
- Права приложения ограничены скоупом `crm` входящего вебхука Bitrix24.

## Сквозная аналитика

Для корректного «Пути клиента» (ТЗ разд. 14.3) адаптер передаёт в лид:

- `SOURCE_ID` — источник/канал брони (маппинг `source_map`);
- `ym_clid`, `etext`, `yclid` — атрибуционные параметры из webhook LitePMS;
- отметка, сумма и дата **оплаты** (событие `booking_module_payment`).

Наличие сквозной аналитики на тарифе портала и список рекламных источников администратор
подтверждает при настройке (ТЗ разд. 14.1–14.2).

## Что требует уточнения (ТЗ разд. 16)

Перед боевым запуском необходимо от заказчика:

1. Готовый URL входящего REST-вебхука Bitrix24 с правами на CRM.
2. Фактические коды пользовательских полей лида (`UF_CRM_*`) для маппинга.
3. Справочник статусов броней LitePMS → стадии воронки лидов.
4. Серверная среда для развёртывания (версия PHP, наличие cron/supervisor, БД).
5. Подтверждение наличия сквозной аналитики на тарифе и рекламных источников.
